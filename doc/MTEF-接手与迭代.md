# MTEF 接手与迭代

公式这块换人接手时，按这份走一遍就能干活。**规则是硬的，背景知识在另外两份里**：
`doc/MTEF-v5-支持说明.md`（新版）和 `doc/MTEF-v3-支持说明.md`（老版），两份都有一节叫
「要加一个模板」和一节「踩过的坑（改代码前请读）」。

## 零、三分钟认清三层

| 层 | 在哪 | 干什么 |
|---|---|---|
| 大门 | `python/mathtype_converter.py` | 取嵌入数据、判版本、分派、兜底。**公式链只有这一个入口** |
| 库 | `python/mathtype/` | `mtef_v5.py`/`mtef_v3.py` 只管「字节 → 结构」；`mtef_v5_latex.py`/`mtef_v3_latex.py` 只管「结构 → LaTeX」；`chars.py` 查符号；`ole_util/` 打开嵌入文件 |
| 验证 | `test/` | 四个自测 + 三个诊断脚本，跟库一起发出去，谁都能跑 |

生产时的顺序：

```text
文档提取器
  → mathtype_converter.py（大门）
     → mathtype/ole_util/ 取出 Equation Native 数据
     → 看数据第一个字节判版本
     → v5：mtef_v5.py → mtef_v5_latex.py
     → v3：mtef_v3.py → mtef_v3_latex.py
     → mathtype/chars.py 查字符与符号名
     → 有结果：进正文当 $...$
     → 拿不准：返回「没有结果」，上层退回那道公式自己的预览图
```

解析和渲染互不知道对方的内部：前一个只认字节，后一个只认结构。改一边不会悄悄带坏另一边。

## 一、验证入口

在任意工作目录下都能跑（位置由 `__file__` 推出来）：

```bash
python test/selftest_v5_parse.py      # 新版：规范范例逐字节、微测试、语料走查
python test/selftest_v5_render.py     # 新版：范例渲染、覆盖项、真机样本比对
python test/selftest_v3_parse.py      # 老版：记录树、样本与语料走查
python test/selftest_v3_render.py     # 老版：408 字符基准逐项对预览图
python test/audit.py                  # 端到端：一份文件里每个公式能不能转出来
python test/peek.py 文件.docx --tree 0 # 诊断：某个对象的明细与结构树
python test/fallback.py               # 验证「转不出来确实退回自己的预览图」
```

判定标准：

| 项 | 合格的标志 |
|---|---|
| 四个自测 | 退出码 0，且打印的结论是「通过」 |
| `audit.py` 跑样本 | 「合计 2 个文件：转出 14、退回 2、空壳 0」 |
| `fallback.py` 跑样本 | 出现「少的那 1 道会退回预览图」 |

**「跳过」不等于「通过」。** 语料目录不在、样本文件不在时，脚本会明确打印「跳过」并按
退出码 0 处理。看到一片绿别急着放心，得看那几行字说的是跳过还是通过。

## 二、改完代码必须过的三道关

1. 四个自测全绿（结论是「通过」，不是「跳过」的那几条要真跑起来）；
2. `test/audit.py` 的数字跟上一版**一模一样**——数字变了就说明生产路径被碰了；
3. `test/fallback.py` 仍然证明「清空一个对象后，转出数少 1」。

三关全过才算没弄坏。只改注释、只改文档可以免跑。

## 三、加一个新构造的标准动作

顺序别颠倒，尤其第 1 步：

1. **先在库里加映射，并确认它「暂时退图」也不算错**。宁可少出一段 LaTeX，不能出一段错的。
2. **登记进覆盖表**：`doc/MTEF-v5-支持说明.md` 第九节的「新增覆盖」栏（v3 那份同理），
   写清「按规范实现、有没有样本验证」。
3. **写进自测**：加进 `test/selftest_v5_render.py` 的覆盖项清单，让它以后每次都被检查。
4. **补一份真机样本**（见第五节），把期望的 LaTeX 写进那张「对答案的表」。
5. **跑三道关**。

## 四、硬闸：不确定就退预览图

任何一处拿不准，就干净地返回「没有结果」：

- 遇到没实现的模板、附饰、字符；
- 槽位数量或矩阵行列数对不上；
- `\left`/`\right` 不配平、花括号不配平；
- 解析没走满（没到 END 就用完字节、有读不懂的记录）。

这四类都算「不确定」。判据都写在库的注释里，改之前先看 `doc/MTEF-*-支持说明.md`
第七节的「踩过的坑」。

## 五、样本从哪来

**真机样本**是这套里唯一的「人」的证据，最值钱：

1. 用 MathType 手写一个式子，导出成 docx（一个 docx 放多个，各自独立）；
2. 把它存进 `python/mathtype/samples/`；
3. 在自测的期望表里逐条写清「第几个对象 → 应该渲染成什么」，空对象写「没有结果」；
4. 跑一遍自测；对不上的就是真 bug。

注意 MathType 自己也有不认的写法（例如 `\widetilde`），那类**造不出样本**，只能按规范实现
并在覆盖表里标「没有样本验证」。现有真机样本是 11 个对象（其中 2 个是空对象）。

另外有两份**三方样本**（`test/samples/`，取自 zhexiao/mtef-go，Apache-2.0）：它们证明
「换一个独立来源的数据，我们读出来跟对方一致」，不依赖任何本机文档。

**语料**（一批真实文档里的公式全量走查）是私人文件，不进仓库。想跑就把 docx/pptx 丢进
`python/mathtype/samples/corpus/`，脚本会自动扫目录、只报告数字、不判定通过与否。

## 六、别找错地方（搬迁后的现状）

- **自测以前长在库文件尾部，现在整段在 `test/selftest_*` 里**。库里只剩解析与渲染，
  没有运行入口、没有样本路径常量、没有基准数值。
- 开发期用过的一批临时探针脚本**没有保留**，文档里提到它们的地方只是当时的记录。
- 那两份说明文档里出现的路径、课件名、论文名是开发记录，已改成中性描述；公众号式的
  「某份课件」不会再出现在仓库里。

## 七、还没验过的构造（想立功就从这儿挑）

下面这些目前一律**退预览图**，要么没实现、要么实现了但没有样本：

- 删除线的横线与下斜、方框的圆角与缺边；
- 箭头的双线、半箭、只有下标签、没有标签；
- 区间号、上下限放在算符正上/正下方的写法；
- v3 那份文档「仅按规范实现，没有样本验证」那一栏里的全部条目。

做这些的路径就一句话：**先读那一节的规范描述 → 按第三节的标准动作做 → 造得出样本最好，
造不出就老实标「没有样本验证」。**

## 出图参数（每次都只有这几项）

提示词是**一个纯文字字符串**，里面不含路径、不含文件名、不含文件 ID、不含任何参数。所有控制项都是独立参数：

| 参数 | 值 | 说明 |
|---|---|---|
| `prompt` | 上面两段文字之一 | 唯一的文字输入 |
| `count` | 1 | 除第一枪是 3，其余都是 1 |
| `ratio` | `1:1` | 图标必须方 |
| `referenceImages` | 2 张（角色图 + 文件夹图） | 会话文件 ID 传入；加过参考图时宿主自动切到 image2image 模式；v2 第一次只传了 1 张 |
| `provider` / `model` | **省略** | 走宿主配置的默认（`之所以ai-gpt生图` / `gpt-image-2.5-sunburst`） |
| `resolution` | **省略** | 只在 v2 第一次传过 `1k`，之后自己摘掉了；尺寸由后处理定 |

## 本文件里为什么会出现路径

文档里的路径全部是**记录**，不是提示词的一部分：

- `hana-downloader/assets/icon.png`：需求里那条，是用户自己指的画风参考，记的是"你说了什么"。
- `D:\Agent\OH-媒体库\...jpg`：成品落到哪里。
- `https://ai.2026886.xyz/v1`：图片网关的地址。

参考图也不是靠路径传的，而是通过另一个参数位 `referenceImages` 传会话文件 ID。提示词文本从头到尾只有中文描述。

## 后续失败的真实原因（探清了）

后面几次全部 `fetch failed`，不是提示词、不是分辨率、也不是参考图——实测证据：

1. 在 shell 里直接探测 `https://ai.2026886.xyz/v1`（图片网关的地址）：`The SSL connection could not be established`；
2. 对照实验：**不传参考图的纯文生图也挂**，同样的 `fetch failed`。

两条证据指着同一件事：到那个网关的链路（TLS 握手）不通。因为**带两张参考图时成功过一次**，说明它不是不支持参考图，而是时好时坏（代理节点/分流规则那类问题）。

下一次带参考图的常规调用（提示词 + 1:1 + 两张参考图，不加分辨率、不指定供应商）如果仍然 `fetch failed`，先查出口再看别的。

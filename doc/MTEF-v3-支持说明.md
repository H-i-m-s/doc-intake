# MTEF v3 支持说明

本文说明 doc-intake 对 **MTEF v3**（Equation Editor 3.x / MathType 3.x，Office 里
progId 为 `Equation.3` 的老公式）的解析与转换：格式怎么分层、代码在哪、验过什么、
什么情况会退回预览图、还有哪些不确定。

面向两类读者：想改这段代码的人，和想知道「为什么这条公式又变成图片了」的人。

---

## 一、这份支持是什么

Office 里的公式有四种来源，doc-intake 分四条路处理：

| 来源 | 标识 | 处理方式 |
|---|---|---|
| OMML（Office 2007+ 原生公式） | `m:oMath` | `extractors/omml_converter.py` |
| MathType（progId `Equation.DSMT4`） | MTEF v5 | `mathtype/mtef.py` |
| **Equation Editor 3.x（本文）** | progId **`Equation.3`**，MTEF v3 | `mathtype/mtef_v3.py` + `mtef_v3_latex.py` |
| 无法解析 | 任意 | 用公式的兜底预览图（WMF/EMF 转 PNG） |

MTEF v3 是四者里最老的一支（Equation Editor 3.0，随 Office 2003 及更早版本分发）。
它的数据躺在 OLE 复合文件的 `Equation Native` 流里。

**这类老公式在课程旧课件里存量很大**，且数据是完整的——能解出 LaTeX，不必退回图片。
本文记录的语料（29 道）来自 `D:\Agent\各种类型文件\[2]第二章_信息与信息论.pptx`。

## 二、数据怎么分层

### 2.1 外层：OLE 与 Equation Native

- 文件里的 OLE 二进制（`.doc`/`.ppt` 内的嵌入对象、OOXML 包里的 `ppt/embeddings/oleObjectN.bin`）
  是 OLE 复合文件，用 `olefile` 或仓库自带的 `ole_util/ole.py` 打开。
- 目标是名为 `Equation Native` 的流（少数写法的流名带 `\x01` 前缀，匹配时要去掉）。
- 流开头是 28 字节的 `EQNOLEFILEHDR`：

  | 偏移 | 长度 | 内容 |
  |---|---|---|
  | 0 | 2 | `cbHdr`，恒为 28 |
  | 2 | 4 | OLE 对象版本 |
  | 6 | 2 | 剪贴板格式 |
  | 8 | 4 | `cbObject`，**后面 MTEF 数据的字节数** |
  | 12 | 16 | 四个保留字段（实测是写它的那个进程留下的指针，值无意义） |

- MTEF body = `流[cbHdr : cbHdr + cbObject]`。`parse_equation_native()` 负责这层，
  `parse(body)` 只吃已剥掉头部的 body。

注意：**有 28 字节头但 `cbObject` 很小（例如 7）的对象是空壳**，body 只有
`FULL` + `END`，没有公式内容。这种对象会正常解析为「空」，随后由调用方退回预览图。

### 2.2 头部：5 字节

| 偏移 | 含义 | 语料实测 |
|---|---|---|
| 0 | MTEF 版本 | 3 |
| 1 | 平台（0=Mac，1=Windows） | 1 |
| 2 | 出品（0=MathType，1=Equation Editor） | 1 |
| 3 | 产品版本 | 3 |
| 4 | 产品子版本 | 1 |

与 v5 不同：v3 头**没有** `mApplication` 字符串，也**没有**内联标志。少读或多读一个
字节，后面会整体错位。

### 2.3 记录流：tag 字节

每个记录以 1 字节开头：**低 4 位是记录类型，高 4 位是选项**。

| 类型 | 名称 | 说明 |
|---|---|---|
| 0 | END | 子对象列表 / 附饰列表的收尾，无数据 |
| 1 | LINE | 行（槽位） |
| 2 | CHAR | 字符 |
| 3 | TMPL | 模板 |
| 4 | PILE | 堆叠（若干行） |
| 5 | MATRIX | 矩阵 |
| 6 | EMBELL | 字符附饰（点、帽、撇号…） |
| 7 | RULER | 制表位 |
| 8 | FONT | 字体名 |
| 9 | SIZE | 字号 |
| 10–14 | FULL / SUB / SUB2 / SYM / SUBSYM | 字号标记，无数据 |

**选项位按记录类型解释**，同一个数值含义不同：

| 位 | LINE | CHAR | 所有结构记录 |
|---|---|---|---|
| 0x1 | `xfNULL`：没有子对象，**连 END 也省略** | `xfAUTO`：可作函数名识别 | — |
| 0x2 | `xfRULER`：后跟 RULER | **`xfEMBELL`：后跟附饰列表** | — |
| 0x4 | `xfLSPACE`：后跟行距 | — | — |
| 0x8 | — | — | `xfLMOVE`：后跟 nudge |

> **这里的 0x1 / 0x2 曾经读反过**，后果见第七节。改动这段代码前请先看那一节。

### 2.4 nudge（位置微调）

带 `xfLMOVE` 的记录后面跟着微调量：

- 两个字节都在 `[-128, 127]` 内：两个字节各偏置 128（即存值 − 128 为真实值）；
- 放不下时：先写两个 `128`，再跟两个 16 位无偏值。

判据是「读到的两个字节**都**是 128」。

### 2.5 字号与下标

`FULL` / `SUB` / `SUB2` / `SYM` / `SUBSYM` 是**行内状态**，影响其后直到下一个标记的
字符。渲染时 `FULL`→0 层、`SUB`→1 层、`SUB2`→2 层，落成 LaTeX 的嵌套下标。

MathType 的「下标字号」不只是变小，**还带基线下降**，所以必须写成 `_{...}` 而不能
平排。依据是 obj4 的预览图：`I(x` `SUB` `i` `)` 显示成下降的小 i（$I(x_i)$），
而不是等大的 `xi`。

### 2.6 子对象列表

LINE / TMPL / PILE / MATRIX / CHAR（附饰）/ EMBELL 之后跟的都是对象列表：
一串记录，**遇 `END` 收尾**。唯一的例外是带 `xfNULL` 的 LINE：子对象列表整段省略，
连 `END` 也没有。

## 三、MATRIX

字段顺序：`valign`、`h_just`、`v_just`、`rows`、`cols`、行分隔线、列分隔线、子对象列表。

- **分隔线各占 `ceil((n+1) × 2 / 8)` 字节**（每行/列间隙 2 bit，各自补齐到字节边界）。
  行分隔线有 `rows+1` 个值，列分隔线有 `cols+1` 个。语料里这些值全是 0（作者没画
  分隔线），所以只按规范补齐字节数，取值仅作记录。
- **子对象列表就是单元：每格一个 LINE**，自左到右、自上而下，共 `rows × cols` 个。
  列表里会夹 `FULL` / `SUB` 这类标记记录，统计时跳过即可。
- 数据里会出现 **1×1 的占位空矩阵**（单元为空），渲染时不输出任何东西。
- 单元数不等于 `rows × cols` 时 `MatrixRec.cell_count_anomaly` 为真，渲染层会
  拒绝并退回预览图。

## 四、模板与槽位顺序

模板记录的字段：`selector`（选择子）、`variation`（变体）、`options`，然后是子对象
列表。**子对象的种类与顺序由选择子所属的「类」决定**，同一个类的槽位位置固定，
空槽以 `xfNULL` 的 LINE 占位（也可能整段省略）。

| 类 | 子对象顺序 | 选择子 |
|---|---|---|
| ParBox 围栏 | 主槽位、左围栏字符、右围栏字符 | 0–12 |
| RootBox 根号 | 主槽位（次数）、被开方槽位 | 13 |
| FracBox 分式 | 分子槽位、分母槽位 | 14 |
| ScrBox 上下标 | 下标槽位、上标槽位 | 15、44 |
| BarBox 上/下划线 | 主槽位 | 16、17 |
| ArroBox 括号箭头 | 主槽位、箭头字符 | 18、19、20 |
| BigOp 大运算符 | 主槽位、**下槽位、上槽位**、运算符字符 | 21–38、42、43 |
| HBrBox 水平花括号 | 主槽位、小槽位、花括号字符 | 27、28 |
| LimBox 极限 | 主槽位、下槽位、上槽位 | 39 |
| LDivBox 长除 | 被除槽位、商槽位 | 40 |
| SlashBox 斜线分式 | 分子槽位、分母槽位 | 41 |
| DiracBox | 左槽位、右槽位、左尖括号、竖线、右尖括号 | 45 |
| VectorBox 箭头 | 主槽位 | 46、47 |
| ArcBox 弧 | 主槽位 | 48 |

### 两处与规范正文不一致，以字节为准

官方规范的「Template Subobject Order」把 BigOp 写成 `upper slot, lower slot`，
**与真实字节不符**。语料里的物证：

- `tmSUM` 变体 1（上下限都有）：两个限位槽依次是「i=2」和「N」→ 下限在前；
- `tmSUM` 变体 0（只有下限）：下限落在第 1 个限位槽；
- `tmSINT/tmSSINT` 的积分上下限：预览图显示 `a` 在下、`b` 在上，而槽位顺序是 a、b。

所以实现取**下限在前**。LimBox 的 `main, lower, upper` 与字节一致，没有争议。

### 上下标的「底」

ScrBox 的子对象**只有下标槽和上标槽**，没有「底」。底是它**前面**那个字符，因此
渲染成后缀（`x` + 下标模板 → `x_{i}`）。选择子 44（前置上下标）的底在后面，渲染
成前缀（`{}_{...}^{...}X`）。

### 限位的数量与摆放

每个选择子的各变体「该有哪些限位」照规范表实现（`BIGOPS` / `LIM_ROLES`）。
「总和式」与「积分式」两种摆放用 `\limits` / `\nolimits` 还原：
`tmSUM` 是上下摆，`tmISUM` 是左右摆；`tmSSINT` 是上下摆，`tmSINT` 是左右摆。
预览图已确认：obj18 的 $\int\limits_{a}^{b}$ 上下摆、obj28 的
$\int\nolimits_{-\infty}^{+\infty}$ 左右摆。

## 五、代码在哪

```text
python/
├── mathtype_converter.py      # 公式转换的统一入口，v3 / v5 在这里分流
└── mathtype/
    ├── mtef.py                # MTEF v5（Equation.DSMT4）
    ├── mtef_v3.py             # 本文主角：v3 字节流 -> 记录树
    ├── mtef_v3_latex.py       # 记录树 -> LaTeX
    ├── chars.py               # 码位 -> LaTeX 符号表
    └── ole_util/              # OLE 复合文件读取
```

分工与边界：

- `mtef_v3.py`：只做「字节 → 记录树」。不产出 LaTeX，不知道公式长什么样。
- `mtef_v3_latex.py`：只做「记录树 → LaTeX」。不读字节。
- `mathtype_converter.py`：`_parse_ole_to_latex()` 先按 v5 解析；v5 读不动时调
  `_parse_v3_to_latex(body)`。

**接入点有三道门**（缺一不可，防止把 v5 数据当 v3 猜）：

1. body 首字节必须是 3（MTEF 版本号）；
2. 头部 `mtef_version` 必须是 3；
3. 解析必须恰好走满 body，且**没有任何 error 提示**。

### 要加一个模板

1. 在 `mtef_v3.py` 的 `TMPL_CLASSES` 里确认选择子归属的类；
2. 在 `mtef_v3_latex.py` 的 `Renderer.tmpl()` 里给该类（或该选择子）加分支；
3. 若涉及限位，补 `BIGOPS` / `LIM_ROLES` 的变体表；
4. 跑第八节的两条自测。

## 六、硬闸与退回策略

一条公式要么给出**完整正确**的 LaTeX，要么退回**它自己的预览图**。中间状态不接受。

`render()` 返回 `None` 的几种情况：

- 遇到没实现的模板或附饰（不猜）；
- 矩阵单元数与行列数不符；
- `\left` 与 `\right` 数量不配对；
- **花括号不配对**（忽略 `\{` `\}` 转义）。

最后一条是补出来的止血闸：它能挡住 `x_{i)` 那类「括号数不对称」的坏输出。
之所以值得单独设一道，是因为它在花括号层面就能判，不必等排版结果。

## 七、踩过的坑（改代码前请读）

### 7.1 CHAR 的附饰位读反了

规范：CHAR 的 0x1 是 `xfAUTO`（可作函数名识别），**0x2 才是 `xfEMBELL`**（后跟附饰
列表）。早期实现挂在 0x1 上。而 v3 里**字母几乎都带 `xfAUTO`**，于是每读到一个字母
就多吞一个「附饰列表」，一直吞到下一个 `END` 为止——后续的括号、等号被吞进子结构，
渲染出 `I(x_{i)=log\frac{1}{P(x_{i)}=-logP(x_{i)}}}` 这种错位结果。

当时只有一份样本，这个错**恰好被另一条补救规则掩盖了**：样本里被吞掉的范围正好
落在合适的位置，外加一条「围栏裁到收尾字形」的启发式把它兜了回来。

换成 29 道的语料后暴露：**12 道渲染成功里有 8 道是坏的**，而硬闸一条都没拦下。
教训是「样本只有一份时，任何巧合都像规律」。

### 7.2 自以为的「矩阵单元摊平」

早期写的 `resolve_matrix_cells()` 会穿过 LINE 容器、丢掉标记与拉伸括号字形来
「摊平」单元。它其实是 7.1 那个错位的产物——子结构被吞乱了，才需要摊平去凑。
附饰位修好之后，矩阵单元就是干净的 LINE 列表，摊平规则整段删除。

### 7.3 矩阵不该自带括号

用 `\begin{bmatrix}` 会画一对括号，外面那层围栏又画一对，视觉上成了 `[[X;P(x)]]`。
MTEF 里矩阵本身不带分隔符，括号只来自围栏，所以用 `\begin{matrix}`。
这类错硬闸拦不住（括号数是对称的），**只能靠看渲染结果**。

## 八、怎么验证

### 8.1 两条自测（可随时跑）

```bash
python mathtype/mtef_v3.py --selftest        # 解析：样本 + 语料的解析质量
python mathtype/mtef_v3_latex.py --selftest  # 渲染：样本与基准逐字比对
```

第一条断言：

- 样本（`SAMPLE_PPTX`，457 字节 body）走满、62 个字符序列逐字对上、6 个矩阵全部
  等于 `rows × cols`；
- 语料（`CORPUS_PPTX`，30 个对象）中 29 个有真实数据，**全部走满且无 error 提示**，
  单元数不符 0 个。

第二条把样本的渲染结果与 `EXPECTED_LATEX`（408 字符）逐字比对。

两个样本路径都写在 `mtef_v3.py` 顶部；文件被挪走或删掉时自测会**跳过并返回 2**，
不会假通过。

### 8.2 对照兜底预览图（人工步骤）

自测只能证明「和上次一样」，不能证明「对」。真正的验收标准是**公式自己的兜底预览图**，
因为它是公式在 PowerPoint/Word 里的真实长相。

流程：

1. 用 slide 的 rels 把每个 OLE 对象与它的预览图配上（`<p:oleObj r:id>` 指向 `.bin`，
   其中的 `<a:blip r:embed>` 指向预览）；
2. 预览通常是 WMF/EMF，用 .NET 的 `System.Drawing` 转成 PNG；
3. 人眼逐张比对。

本次这么做核过 9 张：obj4（下标字号）、obj7（∑ 无上下限）、obj8（矩阵）、
obj13（两个 ∑，且空矩阵处无多余空隙）、obj18 / obj28（积分限位两种摆放）、
obj21（$\sum_i P_i$）、obj24（$\int\limits_R$）、obj25（分段函数的花括号矩阵），
**全部与输出一致**。

临时探针脚本当时放在 `D:\Agent\MTEF-v3-探索\`（`spec_walk.py` 逐字节按规范打印
结构、`report_v3.py` 批量体检、`pair_preview.py` 配预览图），未入库。

## 十、已知不确定项

1. **矩阵分隔线的 2 bit 取值顺序**（首字节高位还是低位）无从验证：语料里八个矩阵
   的分隔线取值全是 0。目前只按规范补齐字节数，取值不影响渲染。若有画了分隔线的
   样本，应补一条自测。
2. **`SIZE` 与 `RULER` 记录的读法沿用 v5 的 `mtef.py`**（mathtypejx 与 Ruby gem 也
   都这么委托），没有单独的 v3 样本可验。
3. **限位「下限在前」是实测结论，与规范正文相反**。规范若在别处（或别的版本）另有
   说法，以字节为准，但要重新核对第四节的物证。
4. 语料全部来自 Equation Editor **3.1**（product=1，版本号 3.1）；MathType 3.x 自己
   写出的 v3 数据（product=0）是否完全同构，未验证。
